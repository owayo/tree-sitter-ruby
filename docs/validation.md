# 構文検証と保守記録（2026-10-08）

tree-sitter-cli 0.27.0 と Rust バインディングで実際の Ruby ソースを検証した。
構文の受理・拒否とブロックの束縛は Ruby 4.0.6 の `ruby -c` と Prism AST を
照合した。Ruby 4.0 の変更点は [公式 NEWS](https://docs.ruby-lang.org/en/master/NEWS/NEWS-4_0_0_md.html)
も確認し、行頭の論理演算子と `*nil` は既存の回帰テストで検証した。

## 確認して修正した不具合

| 再現条件 | 原因と修正 |
|---|---|
| heredoc 本文の `#{1}EOS` や `a\tEOS` の後に本当の終端行がある | interpolation・エスケープ後の行途中を終端としていた。物理行の先頭と、本文を返した後に再開する終端行を区別する |
| heredoc 終端語の後に空白・タブ・単独 CR がある | Ruby が本文として扱う行を終端としていた。LF・CRLF・EOF の境界だけを受理する |
| 終端語 `EOS` に対して本文が `E\t` で始まる | 部分一致した文字を本文として確定せず、エスケープ直前で失っていた。部分一致も本文に含めてトークン終端を記録する |
| 長い heredoc 終端語を保存した状態でリテラルをネストする | リテラル追加時の合計保存容量を確認せず、serialization が 0 を返して状態を失っていた。追加前に共通の容量計算で拒否する |
| 保存データが途中で切れる、または `00 00 01` のように末尾データがある | 復元途中の状態が残る、または assert で終了していた。確保済みの状態も含めて破棄する。空終端語の NULL ポインターへの長さ 0 の memcpy も避ける |
| `$a?0:1`、`@a?0:1`、`@@a?0:1` | 変数を裸のメソッド名として許していたため、`?0` を文字リテラル引数と誤認した。呼び出せる名前を限定し、変数参照との競合では減算と外側の `do` を維持する |
| `for item in build 1` | 列挙対象をコマンド呼び出しのない式に限定していた。括弧なし呼び出しも許可する |
| `1.upto 0 do end.foo(1).bar` と、連結先への `do` ブロック | 連結専用ルールに引数・ブロック・再帰を追加する。再帰のレシーバは名前付きルールを挟み、外側の method フィールドに内側の名前が漏れないようにする |
| `1.upto 0 do end.foo(1) 2` | 連結ルールの引数の後に、もう一組のコマンド引数を付加できた。引数のない頭部を共通化し、二重付加を拒否する |
| `?:'image/gif'` | Ruby の文字リテラルも文字列なのに、後続の引用文字列との暗黙連結を許可していなかった。連結の先頭に文字リテラルを許可する |
| `+ 1.second`、`+value ** 2` | 正の数値リテラルと一般の単項演算を混同し、メソッド呼び出しと冪乗の束縛を誤っていた。数値に隣接する符号を外部トークンで区別し、単項 `+` の優先順位を `**` より高くする |
| `foo + 1.abs, 2` と `foo - 1.abs, 2` | Ruby が拒否する二項演算をコマンド引数として受理していた。単項・二項の外部トークンを分離し、`1..-1` などの範囲終端には式の開始を示す既存のヒントを適用する |
| `return-1`、`return - value`、`break - value`、`next+value` | 符号をキーワードの外側の二項演算としていた。引数の開始位置を示すヒントを渡し、符号と正規表現を引数内で読む。改行で引数が終わることと、異なる字句状態の `yield` も検証する |
| 期待 AST の left / right フィールドを入れ替える | ランナーがフィールド名を常に除去していたため、不一致を見逃した。期待値にフィールド名があるケースでは保持して比較する |
| CMake の configure・install と ts-test | 配布用ヘッダーと pkg-config テンプレートが欠落し、テスト対象も禁止されたコマンドを実行していた。C 配布物を復元し、生成済みソースをビルドして Python コーパスランナーを使う |

スキャナーの分岐は区切り文字や Ruby の字句状態に対応しているため、分岐数だけを
理由に分割していない。共通化したのは保存容量と連結呼び出しの頭部で、どちらも
再現した不具合を防ぐために必要な変更である。クエリや他のバインディングには
修正を必要とする確実な不具合を確認しなかった。

Ruby 本体に残る 5 ファイルは、新しい退行ではない。

- `bad_syntax.rb` と `syntax_error.rb` は、意図的に無効な Ruby を置いた fixture。
- `utf16-be-nobom.rb` と `utf16-le-nobom.rb` は UTF-16 入力。対応する
  `--encoding utf16-be` / `utf16-le` を指定すると両方とも解析に成功する。
- `sample/trick2018/04-colin/entry.rb` は、ローカル変数の束縛に依存する
  三項演算子を含む。以下の有効な Ruby も同じ理由で未対応である。

```ruby
value = 1
value ?"":"fallback"
```

文法がローカル変数の束縛を解決しないため、文字リテラル引数との区別ができず、
`?"` を先に文字リテラルとして読む。`foo ?a` という有効なコマンド呼び出しもあるため、
`?` の字句優先度を一律に上げる変更では両方を維持できない。対応には共有の字句候補と
専用の文法分岐、または束縛を扱う仕組みが必要で、文字リテラルの AST を使う側も
合わせて検証する必要がある。

## テストとビルド

- `python3 scripts/corpus_test.py`: 380 件。
- Python ランナーのユニットテスト: 143 件。
- `cargo test`: 67 件（doc test を含む）。
- Biome、Ruff lint / format、Rust fmt / Clippy、actionlint。
- CMake の共有・静的ライブラリのビルドとインストール、C / C++ 利用側のコンパイル。
- CMake の `ts-test` も同じ 380 件のコーパスを Python ランナーで検証する。
- AddressSanitizer / UndefinedBehaviorSanitizer: 保存状態の復元に 20,000 件の破損入力。

Sonicop 側では同じソース・設定・キャッシュ無効の条件でパーサーだけを交換し、
RuboCop と Rails の全診断をファイル・cop・メッセージ・位置ごとに比較した。
この比較は ERROR が増えていないだけでは見つからない AST の束縛の退行も検出する。
Sonicop 26.9.102 の同一ビルド条件・同一実行ディレクトリで、RuboCop 1.89.0 の
既定設定と Ruby 対象バージョン 4.0 を使った。`.rb` 以外の gemspec なども含むため、
上のパース対象数とは異なる。

| 対象 | ファイル数 | 変更前の診断数 | 変更後の診断数 | 追加 | 削除 |
|---|---:|---:|---:|---:|---:|
| RuboCop | 1,797 | 6,154 | 6,154 | 0 | 0 |
| Rails | 3,575 | 170,781 | 170,781 | 0 | 0 |

両方とも対象ファイル集合と全診断が一致した。途中で見つかった減算・外側の
`do`・括弧付き単項演算の退行は修正し、回帰テストに追加した。

開発ツールは mise.toml で更新し、Biome と cc の依存指定の下限も更新した。
通常の CMake ビルドは生成済みソースを使い、生成とテストは明示的なターゲットに分ける。
